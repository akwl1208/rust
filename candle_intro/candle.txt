================================================================
 Day 55-56 : candle 입문 — Hello Tensor (자세한 설명)
================================================================

이 문서는 main.rs 코드와 짝을 이루는 설명서입니다.
핵심 키워드(candle, burn, Tensor, Device, DType, matmul, shape)를
하나씩 '바싹' 이해하는 것을 목표로 합니다.

큰 그림:
  지금까지 우리는 신경망을 numpy(와 순수 Rust)로 '손수' 만들었다.
  이제부터는 실제 ML 라이브러리를 쓴다. 그 첫 단추가 candle이다.
  numpy로 하던 걸 거의 그대로 하되, Rust의 소유권/에러처리가
  텐서에도 적용된다는 점이 다르다. 그 '다른 점'을 보는 게 이번 핵심.


================================================================
 키워드 1: candle vs burn (두 프레임워크)
================================================================

[candle]
  - Hugging Face가 만든 Rust용 ML 프레임워크.
  - 특징: 가볍고 단순(minimalist). PyTorch처럼 "텐서 + 연산" 중심.
  - numpy/PyTorch를 써봤다면 사고방식이 거의 똑같아 진입이 쉽다.
  - 추론(inference), LLM 돌리기에 강점. (Llama, Whisper 등 예제 풍부)

[burn]
  - 또 다른 Rust ML 프레임워크. 더 '프레임워크'스럽다.
  - 특징: 백엔드 교체 가능(CPU/CUDA/WebGPU/Metal 등)을 타입으로 추상화.
          학습(training) 파이프라인, 모듈 시스템이 더 체계적.
  - 큰 프로젝트/유연성 중시면 burn, 가볍게 시작/추론 중심이면 candle.

[선택 기준 한 줄]
  - "numpy/PyTorch처럼 직관적으로, 빠르게 시작" -> candle
  - "백엔드 유연성, 큰 학습 시스템, 타입 안전한 구조" -> burn
  - 이번 주는 개념이 더 단순한 candle로 텐서 기초를 잡는다.
    (원리를 알면 burn으로 옮기는 건 어렵지 않다)


================================================================
 키워드 2: Tensor (텐서) — 모든 것의 기본
================================================================

[정의]
  텐서 = 숫자들의 다차원 배열. numpy의 ndarray, PyTorch의 Tensor와 같다.
    0차원 = 스칼라 (숫자 하나)
    1차원 = 벡터 ([1, 2, 3])
    2차원 = 행렬 (표)
    3차원+ = 그 이상 (이미지 배치, 시퀀스 등)

[왜 중요한가]
  신경망의 모든 데이터(입력, 가중치, 출력, gradient)가 전부 텐서다.
  우리가 앞에서 Vec<Vec<f64>>로 손수 만들던 행렬을,
  이제 Tensor 하나로 다루고 최적화된 연산을 쓴다.

[생성 방법 (코드 [2]번)]
  Tensor::zeros((2,3), DType::F32, &device)   // 0으로 채움
  Tensor::ones((2,3), DType::F32, &device)    // 1로 채움
  Tensor::randn(0f32, 1f32, (2,3), &device)   // 정규분포 난수(평균0,표준편차1)
  Tensor::from_vec(vec![...], (2,3), &device) // 내 Vec 데이터로
  Tensor::new(&[[1.,2.],[3.,4.]], &device)    // 중첩배열로(shape 자동)

  주의: from_vec은 데이터 개수 == shape 곱 이어야 한다. (6개 = 2*3)


================================================================
 키워드 3: Device (장치) — 연산을 어디서 하나
================================================================

[정의]
  텐서가 '사는 곳'이자 연산이 '일어나는 곳'. CPU 또는 GPU(Cuda).
    let device = Device::Cpu;          // CPU
    let device = Device::new_cuda(0)?; // 0번 GPU

[왜 중요한가 - numpy엔 없던 개념]
  - 모든 텐서는 특정 device에 속한다.
  - CPU 텐서와 GPU 텐서는 '바로' 연산할 수 없다. 같은 곳으로 옮겨야 한다.
    (PyTorch의 .to("cuda")와 같은 맥락)
  - GPU는 행렬 곱 같은 대량 병렬 연산이 CPU보다 수십~수백 배 빠르다.
    그래서 LLM 학습/추론은 GPU에서 한다.

[CPU vs GPU 속도 비교 - 커리큘럼 실습]
  큰 행렬(예: 1000x1000) matmul을 CPU와 GPU에서 각각 돌려
  시간을 재보면 GPU의 위력이 보인다. (GPU 없으면 CPU만)
  코드상 바뀌는 건 device 한 줄뿐 — 나머지 연산 코드는 그대로.
  이게 candle/PyTorch류의 강점: device만 바꾸면 같은 코드가 GPU로 간다.


================================================================
 키워드 4: DType (자료형) — 숫자의 정밀도
================================================================

[정의]
  텐서 원소 하나가 어떤 형식의 숫자인가.
    F64 = 64비트 실수 (정밀, 메모리 많이)
    F32 = 32비트 실수 (딥러닝 기본값)
    F16 = 16비트 실수 (메모리 절반)
    BF16 = bfloat16, 16비트지만 표현 범위가 넓음 (LLM에서 인기)

[왜 중요한가]
  - 정밀도 vs 메모리/속도의 트레이드오프.
  - LLM은 파라미터가 수십억 개라, F32(4바이트)면 메모리가 폭발한다.
    그래서 BF16(2바이트)으로 절반으로 줄여 학습/추론하는 게 표준.
  - "이 모델은 bf16으로 돌린다" 같은 말이 여기서 나온다.

[변환]
  let t64 = t.to_dtype(DType::F64)?;  // F32 -> F64
  서로 다른 dtype끼리는 바로 연산 못 한다(맞춰야 함).


================================================================
 키워드 5: shape (모양) — 텐서의 차원 구조
================================================================

[정의]
  각 축(axis)의 크기. (2,3) = 2행 3열. (4,) = 길이 4 벡터.
    t.shape().dims()  -> [2, 3] 같은 슬라이스
    t.dtype()         -> 자료형 확인

[왜 중요한가]
  - 텐서 연산의 99% 버그가 'shape 안 맞음'이다.
  - matmul은 (m,k)@(k,n)에서 안쪽 k가 일치해야 한다.
  - candle은 shape가 안 맞으면 그 줄에서 에러(Result)를 낸다.
    -> ? 덕분에 즉시 알 수 있다. (numpy보다 안전)

[자주 쓰는 shape 조작]
  reshape((a,b)) : 원소 수 유지하며 모양 바꾸기
  transpose(0,1) : 두 축 교환 (행<->열)
  unsqueeze(0)   : 크기1 축 추가 (2,3)->(1,2,3)
  squeeze(0)     : 크기1 축 제거


================================================================
 키워드 6: matmul (행렬 곱) — 신경망의 핵심 연산
================================================================

[정의]
  진짜 행렬 곱. (2,3) @ (3,2) = (2,2).
    let c = a.matmul(&b)?;

[element-wise mul과의 차이 - 자주 헷갈림!]
  a.mul(&b)    : 같은 위치 원소끼리 곱 (모양 같아야 함). element-wise.
  a.matmul(&b) : 행렬 곱 (선형대수). a의 열 수 == b의 행 수.
  완전히 다른 연산이다! 신경망의 "층"은 matmul이다.
  (Day 45-47에서 본 'output = W @ input + b'의 그 @)

[왜 중요한가]
  신경망 순전파 = matmul의 연속. Transformer도 결국 거대한 matmul 덩어리.
  그래서 GPU가 matmul을 얼마나 빨리 하느냐가 곧 학습 속도다.


================================================================
 ★ 이번 회차의 진짜 핵심: 소유권과 에러처리 (numpy와의 차이)
================================================================

numpy로 a + b 하던 게, candle에선 두 가지가 더 붙는다: & 와 ?

[1] ? (물음표) — 에러 처리
  candle의 거의 모든 연산은 Result<Tensor>를 반환한다.
  성공하면 Tensor, 실패하면 에러. (shape 안 맞음 등)
    let c = a.matmul(&b)?;
  끝의 ?는 "성공하면 값 꺼내고, 실패하면 이 함수를 즉시 끝내며
  에러를 위로 던져라"는 뜻.
  그래서 main이 Result를 반환하도록 선언했다(-> Result<...>).
  마지막에 Ok(()) 로 "성공으로 끝남"을 알린다.

  왜 이렇게? Rust는 "실패할 수 있는 일"을 타입으로 강제한다.
  numpy는 런타임에 갑자기 터지지만, candle은 '여기서 실패 가능'을
  코드에 ?로 명시하게 해서 더 안전하다.

[2] & (앰퍼샌드) — 빌림(borrow), 소유권
  연산 메서드는 인자를 빌려서(&) 받는다:
    let sum = t.add(&o)?;   // &o : o를 '빌려준다'
  왜 &가 필요한가?
    Rust에선 값을 그냥 넘기면 '소유권'이 넘어간다.
    만약 t.add(o) 처럼 &없이 넘기면, o의 소유권이 add로 넘어가
    그 뒤로 o를 다시 못 쓰게 된다(move).
    &o로 '빌려주면' o는 그대로 살아있어서 계속 쓸 수 있다.

  이게 커리큘럼이 말한 "왜 이걸 clone/빌림 해야 하나가 보인다".
    - 빌림(&)으로 충분하면 & 사용 (복사 안 함, 효율적)
    - 소유권이 진짜 필요하거나 원본 보존하며 복제하려면 .clone()
  numpy엔 이런 고민이 없다(파이썬이 알아서 참조 관리).
  Rust는 메모리 안전을 위해 이걸 프로그래머가 명시하게 한다.

[브로드캐스트도 명시적]
  numpy: a + bias 가 모양 다르면 자동으로 맞춰 더함(broadcast).
  candle: 명시적으로 broadcast_add 를 써야 한다:
    let out = a.broadcast_add(&bias)?;
  "암묵적 마법"을 줄이고 의도를 코드에 드러내는 Rust 철학.


================================================================
 집계 연산 정리 (sum, mean)
================================================================

  sum_all() / mean_all()  : 전체 원소 합/평균 -> 스칼라(0차원)
       값 꺼내기: .to_scalar::<f32>()?
  sum(0) / sum(1)         : 특정 축으로 합
       axis=0 : 행 방향으로 더함 -> 열별 합
       axis=1 : 열 방향으로 더함 -> 행별 합
  sum_keepdim(1)          : 더한 축을 1로 남김 (차원 유지)
       -> 브로드캐스트에 유용 (LayerNorm의 평균 빼기 등)
  값 꺼내기:
       1D 텐서 -> .to_vec1::<f32>()?
       2D 텐서 -> .to_vec2::<f32>()?

================================================================
 전체 한 장 요약
================================================================

  Tensor   숫자의 다차원 배열 (모든 데이터/가중치)
  Device   연산 장소 (Cpu / Cuda) — 텐서마다 소속, GPU가 빠름
  DType    숫자 정밀도 (F32 기본, BF16은 LLM 메모리 절약)
  shape    차원 구조 (2,3)=2x3. 버그의 90%가 shape 불일치
  matmul   행렬 곱(@). element-wise mul과 다름. 신경망의 핵심
  candle   가벼운 Rust ML 프레임워크 (numpy+PyTorch 역할)
  burn     더 체계적/유연한 Rust ML 프레임워크 (백엔드 추상화)

  numpy와의 핵심 차이 두 가지:
    ?  = 연산이 Result를 반환 (실패 가능을 타입으로 강제, 안전)
    &  = 인자를 빌림 (소유권을 안 넘김. "왜 clone하나"의 이유)

한 줄 결론:
  candle은 "numpy를 Rust답게" 만든 것이다. 연산은 거의 같고,
  소유권(&)과 에러처리(?)라는 Rust의 안전장치가 텐서에도 붙는다.
