================================================================
 큰 그림: 이번 회차는 왜 배우나?
================================================================

지금까지(Day 45-50) 우리는 신경망을 만들고, 순전파-역전파로
학습시키는 '기본 원리'를 배웠습니다.

그런데 그 기본만으로는 '진짜 큰' 신경망(LLM 같은)은 학습이 안 됩니다.
층을 수십~수백 개 쌓으면 값이 폭주하거나 사라져서 학습이 망가져요.

이번 회차는 그 '큰 신경망을 실제로 굴러가게 만드는 보조 장치'들입니다.
자동차로 치면, 엔진(순전파/역전파)은 이미 배웠고
이번엔 브레이크, 안전벨트, 서스펜션 같은 '안정 장치'를 배우는 거예요.

  - LayerNorm        : 값이 폭주하지 않게 매번 정돈 (서스펜션)
  - Dropout          : 과적합 방지 (한 부품에만 의존하지 않게)
  - Gradient Clipping: gradient 폭발 막기 (브레이크)
  - 미니배치          : 데이터를 묶어서 효율적으로 처리 (적재 방식)

핵심 동기:
  "LLaMA 같은 LLM 코드를 열어보면 곳곳에 LayerNorm과
   gradient clipping이 박혀 있다. 그게 왜 거기 있는지
   이해하면 모델 코드를 읽을 수 있다."


================================================================
 1. 미니배치(mini-batch) — 데이터를 묶어서 처리
================================================================

[무엇인가]
  데이터를 한 개씩 처리하지 않고, 여러 개를 한 묶음으로 만들어
  한꺼번에 처리하는 것.

[비유: 택배]
  편지 100통을 부친다고 하자.
    - 한 개씩: 우체국에 100번 왕복 (느림)
    - 묶어서: 100통을 한 상자에 담아 한 번에 (빠름)
  미니배치 = 데이터를 상자에 담는 것.

[shape (모양) 이야기]
  배치는 보통 [batch, features] 모양의 표(행렬)로 표현한다.
    batch    = 묶음 안에 든 샘플 개수 (상자 안 편지 수)
    features = 샘플 하나가 가진 숫자 개수 (편지 한 통의 내용 길이)

  예) [batch=2, features=4]
        [1, 2, 3, 4]   <- 샘플 1
        [2, 4, 6, 8]   <- 샘플 2
      = 2행 4열짜리 표.

  코드에서 "배치된 것"은 바로 이 표다:
        let batch = vec![
            vec![1.0, 2.0, 3.0, 4.0],  // 샘플 1
            vec![2.0, 4.0, 6.0, 8.0],  // 샘플 2
        ];
  바깥 묶음 = 배치, 안쪽 하나하나 = 샘플.
  (demo_minibatch 함수는 이 표를 '보여주기'만 한다. 계산은 안 함.)

[왜 중요한가]
  1) 효율: 컴퓨터(특히 GPU)는 표 하나를 통째로 곱하는 걸 잘한다.
           한 개씩 100번보다 100개를 한 번에가 훨씬 빠르다.
  2) 안정성: 한 샘플만 보고 가중치를 고치면 들쭉날쭉하다.
            여러 샘플의 '평균 방향'으로 고치면 학습이 매끄럽다.

  => 이후 모든 처리(LayerNorm 등)는 이 표를 한꺼번에 다룬다.


================================================================
 2. LayerNorm — 매번 값을 정돈하기 (이번 회차의 주인공)
================================================================

[먼저: 왜 정규화가 필요한가]
  신경망은 층을 거칠 때마다 숫자를 곱하고 더한다.
  층이 깊으면 이 숫자가 점점 커지거나(폭주) 작아진다(소멸).
    예) 1.5배씩 50층 -> 1.5^50 = 어마어마하게 큰 수 -> 학습 붕괴
  그래서 각 층마다 값을 '적당한 범위로 다시 맞춰주는' 장치가 필요하다.

[무엇인가]
  한 샘플 안의 숫자들을 '평균 0, 퍼짐(분산) 1'로 다시 맞추는 것.
  비유: 시험 점수를 평균 50, 표준편차 10짜리 표준점수로 바꾸는 것과 비슷.
        원점수가 들쭉날쭉해도 정규화하면 일정한 스케일이 된다.

  그 다음, 학습 가능한 손잡이 두 개로 미세 조정한다:
    gamma(감마) = 얼마나 키울지 (스케일)
    beta(베타)  = 얼마나 옮길지 (이동)
  (처음엔 gamma=1, beta=0 으로 둬서 '그대로 정규화만' 상태)

[정규화 '방향'이 핵심 - 그림으로]
  배치를 표로 보면:
              feature1 feature2 feature3 feature4
    샘플1        1        2        3        4
    샘플2        2        4        6        8

  LayerNorm = '가로(행)' 방향으로 정규화
     -> 샘플1의 [1,2,3,4]를 자기들끼리 평균0/분산1로
     -> 샘플2의 [2,4,6,8]을 자기들끼리 평균0/분산1로
     -> 즉 '각 샘플을 독립적으로' 정돈.

[왜 LLM은 LayerNorm을 쓰나 - 가장 중요]
  - 샘플 하나만 있어도 정규화가 된다 (자기 안에서만 계산하니까).
  - 배치 크기가 1이든 100이든 결과가 똑같다 (배치에 안 휘둘림).
  - 문장 길이가 제각각인 언어 데이터에 딱 맞는다.
  => 그래서 GPT, LLaMA 등 모든 LLM이 LayerNorm을 표준으로 쓴다.

  코드에서 직접 만든 LayerNorm이 PyTorch(검증된 라이브러리)의
  결과와 '오차 0.0'으로 똑같았다 -> 제대로 구현했다는 증거.


================================================================
 3. BatchNorm — 비교용 (LayerNorm과 뭐가 다른가)
================================================================

[무엇인가]
  LayerNorm과 비슷하지만 정규화 '방향'이 90도 다르다.
  BatchNorm = '세로(열)' 방향으로 정규화.

  같은 표에서:
              feature1 feature2 feature3 feature4
    샘플1        1        2        3        4
    샘플2        2        4        6        8

  BatchNorm = feature1끼리(1,2), feature2끼리(2,4)... 세로로 정규화.
     -> '배치 안 여러 샘플'을 모아야 계산이 된다.

[왜 LLM엔 안 맞나]
  - 세로로 정규화하니 '배치 안에 샘플이 여러 개' 있어야 한다.
  - 배치가 작거나(1개) 문장 길이가 들쭉날쭉하면 통계가 불안정.
  => 그래서 LLM은 BatchNorm 대신 LayerNorm을 쓴다.
     (BatchNorm은 이미지 처리(CNN) 같은 데서 주로 쓰임)

한 줄 요약:
  LayerNorm = 가로(샘플별) 정규화, 배치 크기 무관 -> LLM
  BatchNorm = 세로(feature별) 정규화, 배치에 의존 -> CNN

 4. Dropout — 과적합 방지 (학습/추론 모드가 핵심)
================================================================

[무엇인가]
  학습 중에 뉴런(계산 단위) 일부를 '무작위로 꺼버리는' 것.
  매번 다른 뉴런을 끈다.

[비유: 공부 그룹]
  한 조에서 항상 똑똑한 한 명한테만 의존하면, 그 친구가 빠지면
  조 전체가 무너진다. 일부러 가끔 한 명씩 빠지게 하면, 나머지도
  골고루 실력이 는다 -> 누가 빠져도 잘하는 튼튼한 조가 된다.
  Dropout = 신경망이 특정 뉴런에만 의존하지 못하게 막는 것.
            => 과적합(특정 패턴 암기) 방지.

[학습 모드 vs 추론 모드 - 이게 진짜 핵심]
  학습할 때(training):
     확률 p로 뉴런을 끈다. (예: p=0.5면 절반을 무작위로 0으로)
     살아남은 뉴런은 1/(1-p)배로 키운다. (꺼진 만큼 보충)
     -> 왜 키우나? 절반이 꺼지면 전체 합이 절반으로 줄어드니까,
        남은 걸 2배 키워서 '평균 크기'를 원래대로 유지한다.

  예측할 때(inference):
     아무것도 끄지 않는다. 모든 뉴런을 다 쓴다.
     -> 실전에선 가진 능력을 전부 발휘해야 하니까.

  이 '두 모드가 다르게 동작한다'는 점이 Dropout의 핵심.
  (학습 땐 일부러 약하게, 예측 땐 풀파워)

[검증]
  학습 모드 출력의 평균이 입력 평균(1.0)과 거의 같았다(0.99...).
  -> 1/(1-p) 보정 덕에 크기가 유지된다는 증거.


================================================================
 5. Gradient Clipping — gradient 폭발 막기 (브레이크)
================================================================

[먼저: gradient 폭발이 뭔가]
  역전파로 구하는 gradient(가중치 고칠 방향+크기)가
  가끔 갑자기 엄청 커질 때가 있다.
  그러면 가중치가 확 튀어버려서 학습이 망가지고,
  심하면 loss가 NaN(숫자 아님)으로 터진다.

[무엇인가]
  gradient의 전체 크기(norm)가 정한 한계(max_norm)를 넘으면,
  '방향은 그대로 두고 크기만' 한계치로 줄인다.

[비유: 자동차 속도 제한]
  내리막에서 차가 너무 빨라지면 위험하다.
  가는 '방향'은 그대로 두되 '속도'만 제한선으로 낮춘다.
  Gradient Clipping = gradient의 속도 제한 장치.

  예) gradient [3, 4] 의 크기 = 5.
      한계 1로 clip -> [0.6, 0.8] (크기 1, 방향은 동일)
      가리키는 쪽은 같고 길이만 5에서 1로 줄었다.

[왜 중요한가]
  LLM처럼 크고 깊은 모델은 gradient 폭발이 자주 일어난다.
  clipping이 없으면 학습 도중 갑자기 터진다.
  => LLM 학습에서 거의 필수 안전장치.


================================================================
 전체 한 장 요약
================================================================

  미니배치     데이터를 표로 묶어 한 번에 처리 (효율 + 안정)
  LayerNorm    각 샘플을 평균0/분산1로 정돈, 배치 무관 -> LLM 표준
  BatchNorm    feature별 정규화, 배치 의존 -> CNN용 (비교 대상)
  Dropout      뉴런 무작위로 끄기(학습)/다 쓰기(추론) -> 과적합 방지
  Grad Clip    gradient 크기 제한 -> 폭발 방지 (방향은 유지)

왜 배우나 (한 문장):
  순전파/역전파라는 '엔진'만으로는 큰 신경망이 안 굴러간다.
  LayerNorm/Dropout/Clipping 같은 '안정 장치'가 있어야
  LLM처럼 깊은 모델이 안 터지고 학습된다.
  그래서 LLaMA 코드 곳곳에 이것들이 박혀 있는 것이고,
  원리를 알면 그 코드가 읽힌다.
